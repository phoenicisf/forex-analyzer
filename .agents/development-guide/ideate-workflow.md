# Idea Refinement (Phase 0) — Development Guide

คู่มือการใช้งาน Phase 0 Idea Refinement — optional pre-phase ก่อน Phase 1 BA เพื่อแปลง vague idea / pain point → BA-Ready Brief

---

## เมื่อไหร่ควรใช้ Phase 0

**ใช้เมื่อ:**
- เริ่มจาก pain point / opportunity ที่ยังไม่ชัดว่า scope คืออะไร
- Stakeholder มี "idea" แต่ยังไม่มี problem statement ที่ BA เขียนได้
- มีหลาย direction เป็นไปได้ ต้องการ explore + commit ก่อน BA

**ข้ามได้เมื่อ:**
- มี BRD / PRD พร้อมแล้ว (scope ถูกกำหนด)
- Brownfield project ที่ scope ชัดจาก existing system
- Feature small พอที่ BA เริ่มได้เลย (ใช้ `/amend ba` ดีกว่า)

## Step-by-Step: ต้องทำอะไร พิมพ์อะไร

### Step 1: เตรียม Input (optional)

กรอก `docs/foundation-input-sources/project-overview.md` + `stakeholder-input.md` ถ้ามีข้อมูล — ไม่จำเป็นแต่ช่วยให้ facilitator มี context

### Step 2: สั่ง `/ideate`

**Single-shot mode** (ถ้ามี pain point ชัด 1 ประโยค):

```
/ideate "Back-Office Admin ใช้เวลา 30 นาทีต่อ order เพื่อ resolve stuck payment"
```

Agent จะทำ 4 steps ต่อเนื่อง, present brief ฉบับร่าง → รอ user review ก่อน write

**Interactive mode** (ถ้ายังไม่ชัด):

```
/ideate
```

Agent จะถามทีละ step — user ตอบเป็นรอบ

**Resume mode** (ถ้าเคยทำ Phase 0 แล้วอยาก pivot / extend):

```
/ideate resume
```

Agent อ่าน brief เดิม → ถาม append / overwrite / refine

### Step 3: Review Brief

เปิด `docs/foundation-input-sources/ideation-brief.md` ตรวจ:

- HMW question ตรงกับ pain point จริง?
- Chosen direction มี rationale ทั้ง 3 axes (BV/F/R)?
- "Not Doing" list ครอบคลุม scope exclusions ที่ stakeholder คาดหวัง?
- Open questions ครบ — BA เริ่มทำ interview guide ได้ไหม?

ถ้าอยากแก้ → `/ideate resume` แล้วเลือก refine section

### Step 4: ไป Phase 1 BA

ไม่ต้อง copy-paste — BA workflow อ่าน brief ให้อัตโนมัติ:

```
/ba                              # default — agent อ่าน ideation-brief + project-overview
/ba "<focus hint>"               # ถ้าต้องการ scope hint เพิ่ม (เช่น "MVP only")
```

`/ba` workflow wraps `.agents/prompt-templates/ba-requirements-prompt.md` (authoritative content) + ทำ Phase 0 onboarding ให้อัตโนมัติ

BA จะ:
- ใช้ §1 HMW + context เป็น starting point ของ `docs/ba/01-project-brief.md`
- ใช้ §2 chosen direction เป็น scope boundary
- ใช้ §5 not-doing list เป็น explicit out-of-scope ใน brief
- ใช้ §6 open questions เป็น stakeholder interview guide

## ตัวอย่าง: BA-Ready Brief ที่สมบูรณ์

```markdown
# Ideation Brief — Back-Office Order Resolution Speedup

> Generated by Phase 0 Idea Refinement on 2025-04-20
> Status: ready-for-ba

---

## 1. Problem Statement (HMW)

**HMW:** How might we reduce Back-Office Admin's average resolution time for stuck payment orders from 30 minutes to under 5 minutes, without increasing error rate?

**Context:**
- Pain point: Admins ต้องเปิด 4 tabs (order DB, payment gateway, CRM, email) ต่อ 1 case
- Current state: avg 30 min/order, 40 orders/day per admin, 12% re-open rate
- Desired outcome: ≤5 min/order, same volume, ≤5% re-open

**Primary stakeholder:** Back-Office Admin (n=8)
**Success signal:** P50 resolution time on weekly dashboard

---

## 2. Chosen Direction

**Title:** Unified Resolution Console

**Description:**
- Single-pane view of order + payment + customer + communication history
- Scripted resolution playbooks (top-5 stuck reasons)
- One-click action: refund / retry / escalate พร้อม audit trail
- Read-only integration กับ existing payment gateway + CRM (ไม่ต้อง rebuild)

**Why this one:**
- Business value: **High** — attack P50 + re-open rate พร้อมกัน
- Feasibility: **Medium** — need API integration แต่ read-only scope manageable
- Risk: **Medium** — playbook coverage ต้อง validate กับ admin team

**Lens origin:** Simplification (เดิม 4 tabs → 1 console)

---

## 3. Alternate Direction

**Title:** AI Copilot in Existing Tools

(…rationale omitted for brevity…)

---

## 4. Variations Considered

| # | Title | Lens | Score (BV/F/R) | Decision |
|---|-------|------|----------------|----------|
| 1 | Unified Resolution Console | Simplification | H/M/M | ✅ chosen |
| 2 | AI Copilot in Existing Tools | Audience Shift | M/M/H | 🔄 alternate |
| 3 | Auto-resolve bot (no human) | 10x Scale | H/L/H | ❌ not doing — risk too high for MVP |
| 4 | Revert to manual-only + SLA | Inversion | L/H/L | ❌ not doing — doesn't solve pain |
| 5 | Outsource resolution to vendor | Constraint Removal | M/M/M | ❌ not doing — stakeholder wants in-house |

---

## 5. Not Doing

- **Auto-resolve bot** — risk of wrong refunds สูงใน MVP; revisit after 6 months of console data
- **Mobile app for admins** — out of scope; admins work at desks
- **Customer-facing self-service** — different problem space; separate initiative

---

## 6. Open Questions for BA

- [ ] Playbook coverage: top-5 stuck reasons รวมกี่ % ของ cases จริง?
- [ ] Admin team approval process สำหรับ one-click refund > threshold?
- [ ] Integration SLA กับ payment gateway — read-only มี rate limit ไหม?
- [ ] Historical data migration — ต้องเอา order history ย้อนกี่เดือน?

---

## 7. Input Sources Used

- `project-overview.md` — domain = e-commerce back-office
- `stakeholder-input.md` — admin team pain points, current SLA

---

## 8. Handoff Note

> **To Phase 1 BA:** §1 HMW = scope anchor; §2 Unified Resolution Console = MVP direction; §5 not-doing list = explicit out-of-scope; §6 open questions = admin interview guide (round 1)
```

## Common Pitfalls

| Pitfall | แก้ยังไง |
|---------|----------|
| HMW กว้างเกิน ("HMW ทำให้ระบบดีขึ้น") | เพิ่ม measurable outcome + specific stakeholder |
| Variations ซ้ำๆ (5 variations, ทั้งหมดเป็น "เพิ่ม UI ปุ่มนั้นปุ่มนี้") | บังคับใช้ ≥3 lenses ต่างกัน — lens = forcing function |
| ไม่มี "Not Doing" list | convergence ไม่เกิด — ต้อง explicit ว่าตัดอะไร + เหตุผล |
| Brief มี tech stack ("ใช้ React + PostgreSQL") | Violate Phase 0 rule — remove, ให้ Architect ตัดสินใจใน Phase 1B |
| Open questions ว่าง | BA ไม่มีอะไรทำต่อ — เพิ่มอย่างน้อย 2 ข้อ |

## Relationship กับ Phases อื่น

| Phase | Relationship |
|-------|-------------|
| Phase 1A (BA) | Consumes `ideation-brief.md` as input — ไม่ blocking (BA รันได้แม้ไม่มี brief) |
| Phase 1B (SD) | Ignores brief (อ่าน BA docs แทน) |
| `/amend` | ไม่ใช้ `/amend` แก้ brief — ใช้ `/ideate resume` แทน |
| `/backtrack` | Phase 0 ไม่ใช่ backtrack target — แต่ user รัน `/ideate resume` แล้วตามด้วย `/backtrack ba` ได้ถ้า pivot ระดับ idea |
| `/next` | Detect จะแนะนำ `/ideate` ถ้า `docs/ba/` ว่าง + ไม่มี `ideation-brief.md` และ user เริ่มจาก vague idea |
